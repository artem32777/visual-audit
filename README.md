# Visual Audit

Скилл проверяет вёрстку (pixel perfect) блока или страницы целиком на соответствие фреймам Figma или изображениям
и создаёт отчёт с инструкциями для правок.

## Алгоритм работы

1. Один раз склонируй репо в папку с локальными скиллами (например, `C:\Users\artem\.agents\skills\`).
2. Открой чат проекта, напиши название элемента, который нужно протестировать и передай ссылки на эталоны для сравнения. 
3. Дождись формирование отчёта, проанализируй его, скопируй инструкции для правок и передай их агенту.

## Промт

- Скилл вызывается в чате с помощью спецсимвола (в кодексе $, в курорсе / ) и команды `$visual-audit`.
Либо с помощью указания прямого пути папки скилла.
- Агент ожидает на вход название или ссылку на компонент / группу компонентов / страницу.
И эталоны: ссылки на фреймы Figma или изображения в масштабе 1:1. Эталонов может быть сразу несколько если это адаптивы. Каждый проверяется отдельно на своей ширине: для Figma — ширине фрейма, для картинки — ширине исходного изображения. Фиксированных брейкпоинтов нет; один эталон достаточен, три эталона дают три проверки. 
- Форматирование промта может быть любым, агент сам разберётся. Например:

```text
Сделай $visual-audit. Страница: Избранное. <ссылка на desktop фрейм Figma>, <ссылка на mobile фрейм Figma>.
```

## Время выполнения, расход токенов, разница моделей.

- Агент запустит в своей песочнице локальный дев-сервер согласно настройкам package.json
или вы можете в промпте сразу ему прислать ссылку на уже запущенную страницу, где делали вёртску.
- Можно дать дополнительные инструкции в промпте: проверить на странице только определенный блок или
сделать нужное состояние, ховеры и т.п.


- Если переданы только названия компонентов или UI-сценарий, агент создаёт временную моковую страницу в проекте с реальными компонентами и нужным состоянием. Скриншоты снимаются с этой страницы; Storybook не используется. После съёмки агент убирает созданные для аудита временные файлы, сохраняя отчёт и пользовательские изменения.

- Артефакты аудита сохраняются в корне проверяемого проекта в `.log/visual-audit/`. Каждый новый запрос, в том числе повторная проверка после правок, создаёт уникальный каталог запуска с config.json и эталонами; новые снимки, сравнение, замечания и HTML-отчёт лежат в его подкаталоге `results/`. Старый отчёт не выдаётся вместо новой проверки.
