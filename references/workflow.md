# Форматы и запуск

`<skill>` — абсолютный путь к visual-audit. Node >=22. Зависимости: `npm ci` из каталога скилла. На Windows при установленном Edge укажи `"channel": "msedge"`. Иначе используй Chromium Playwright (`npx playwright install chromium`, если ещё не установлен). Окружение браузера сохраняй одинаковым между повторными запусками.

В корне проверяемого проекта создай `.log/visual-audit/`. Все артефакты аудита храни внутри неё, вне директории скилла. Для каждого нового запроса на проверку создай новый уникальный каталог запуска, например `.log/visual-audit/2026-10-02-120000-a1b2/`: в нём размести config.json, исходные PNG и при необходимости prepare.mjs, а `output` задай как `results`. Скрипт capture создаёт этот подкаталог сам; заранее его не создавай. Снимки, JSON и report.html сохраняются в `results/`. Заново выполни capture, compare, визуальный анализ и report. Результаты предыдущего запуска не подставляй в новый. Старые отчёты не перезаписываются.

## config.json

Одна запись views на каждый переданный пользователем эталон: ссылку на фрейм Figma или изображение. Один эталон полностью достаточен; не требуй ещё два адаптива. Пример для одного фрейма шириной 1440 px:

```json
{
  "title": "Каталог",
  "url": "http://localhost:3000/catalog",
  "output": "results",
  "threshold": 0.1,
  "notes": [],
  "views": [
    {
      "id": "desktop",
      "width": 1440,
      "viewportHeight": 900,
      "design": "design/desktop.png",
      "figmaUrl": "https://www.figma.com/design/FILE/Name?node-id=1-2"
    }
  ]
}
```

Для нескольких ссылок или изображений добавь записи с фактической шириной каждого эталона. Для изображения укажи design как путь к исходному PNG, а figmaUrl и designVersion опусти. Другие форматы предварительно преобразуй в PNG без изменения размеров. Ширина картинки в пикселях задаёт ширину браузера в CSS px при DPR=1. Не используй заранее заданные desktop/tablet/mobile-ширины. REST-экспорт сам читает width из Figma и записывает в config; если width уже указан, проверяет совпадение. При оригиналах из MCP агент берёт width из метаданных фрейма и проверяет PNG 1x. Если width пропущен при съёмке, он определяется по PNG; для Figma это допустимо только для оригинального 1x-экспорта, не превью; для переданной картинки используется её исходная ширина.

`id` — уникальное имя (`desktop`, `tablet`, `mobile` либо другое); можно опустить, тогда назначается `frame-1`, `frame-2`, … в порядке ссылок. Фреймы одинаковой ширины поддерживаются отдельно. Каталоги результатов названы по id. Имена допускают буквы ASCII, цифры, дефис и подчёркивание.

Ширина — положительное целое число CSS px. Дробный размер не округляй молча: уточни его. Высота окна по умолчанию 900 px, может задаваться в viewportHeight; высоту длинного макета не используй как высоту окна. Относительные пути разрешаются от config.json. `threshold` — чувствительность цвета 0..1 для pixelmatch, не процент допустимых ошибок. PNG должен совпадать с width без изменения масштаба. `designVersion` опционально фиксирует версию Figma.

Опциональные поля: `locale` (ru-RU), `readySelector` (ожидание готовой страницы), `storageState` (локальный файл авторизации), `prepare` (локальный модуль подготовки). Авторизация не попадает в отчёт/репозиторий. prepare экспортирует `export default async (page, width) => { ... }`; используй для предусмотренного макетом состояния. Аудит не даёт разрешения отправлять формы, заявки или сообщения. Подготовку опиши в notes. Если два фрейма одной ширины требуют разных состояний, используй отдельные config/run с разными prepare.

`captureSelector` выбирает всю проверяемую секцию. Его и `readySelector` можно задать в config или переопределить
для конкретного view. Каждый селектор должен совпасть ровно с одним видимым элементом. При динамической загрузке
скрипт сначала ждёт первое совпадение в DOM, затем проверяет уникальность и видимость; ошибку выводит с названием поля.
Результаты создаются после успешного запуска браузера, открытия страницы и проверки селекторов.

При captureSelector скрипт вырезает вертикальный диапазон секции из полного стабильного снимка, сохраняя всю
ширину (включая горизонтальное переполнение), положение по x и внутренние отступы. Масштаб не меняется.
Границы округляются наружу до целых пикселей; дробная граница может добавить 1 px. `actual-full-page.png`
сохраняет страницу целиком, `capture-region.json` и capture.json — координаты и исходные bounds элемента.
В отчёте предупреждение явно указывает, что внешнее положение секции среди остальных блоков не сравнивается.
Координаты issues относятся к вырезке actual.png. Не применяй режим секции к эталону целой страницы.

## Команды

```text
node <skill>/scripts/run.mjs capture <config.json>
node <skill>/scripts/run.mjs report <results-directory>
node <skill>/scripts/export-figma.mjs <config.json>
node <skill>/scripts/capture.mjs <config.json>
node <skill>/scripts/compare.mjs <run-directory>
node <skill>/scripts/crop.mjs <input.png> <output.png> <x> <y> <width> <height>
node <skill>/scripts/report.mjs <run-directory>
```

Предпочитай две команды run.mjs: первая делает capture + compare, вторая после визуального анализа
делает report + verify-report. Старые отдельные команды сохранены для диагностики и совместимости.
`verify-report.mjs <results-directory> [channel]` проверяет все views и режимы в локальном Playwright,
изображения, масштабы, области замечаний и отсутствие обрезки текста карточек. На Windows используется
channel из capture.json (например msedge). `report-check.json` содержит статус и выполненные проверки;
ошибка даёт ненулевой exit code. Это техническая проверка HTML, не оценка соответствия макету.
`timing.json` и `report-timing.json` сохраняют длительности стадий в миллисекундах.

В PowerShell заключай селекторы, пути с пробелами и ссылки вида `@e6` в одинарные кавычки.

export-figma пропускает записи без figmaUrl; для запуска только с готовыми изображениями его не вызывай. Он нужен только для REST-экспорта и требует FIGMA_TOKEN из окружения. Токен передаётся лишь в заголовке Figma API; PNG скачивается без него. Скрипт определяет ширину, фиксирует версию файла и скачивает все запрошенные изображения до записи. Не перезаписывает существующие PNG. При ошибке/429 сообщает код, без бесконечных повторов. Подключение MCP не означает наличие REST-токена.

capture.json содержит id фреймов, параметры браузера и предупреждения. comparison.json добавляет размеры, разницу высот, pixelmatch и список полос. Цветовой diff исключает обнаруженное сглаживание (includeAA=false), не маскирует текст, не выравнивает блоки. Прозрачные пиксели для расчёта компонуются на белом; оригиналы сохранены. Недостающая площадь красная даже при белом фоне обеих картинок. Переполнение не обрезается. Полосы лежат в `<id>/tiles`; y — координата в полном изображении.

## issues.json

```json
{
  "reviewedViews": ["desktop"],
  "issues": [
    {
      "id": "V01",
      "viewId": "desktop",
      "severity": "minor",
      "where": "Первый экран, заголовок",
      "description": "Заголовок занимает три строки вместо двух в макете.",
      "suggestion": "Проверить типографику и доступную ширину текста.",
      "region": {"x": 80, "y": 140, "width": 600, "height": 150},
      "designRegion": {"x": 80, "y": 140, "width": 600, "height": 100}
    }
  ]
}
```

`viewId` ссылается на фрейм из comparison.json. Ширина подставляется в отчёт автоматически. `severity`: major — крупное, minor — заметное, detail — мелкое. `suggestion` необязателен; короткая подсказка для карточки, не план исправлений.

`region` обязателен и относится к actual.png; `designRegion` необязателен, относится к design.png. Указывай оба при смещениях. Без designRegion используется та же область координат с явной подписью. Координаты полных оригиналов при DPR1, не превью и не полосы. Прямоугольники лежат в пределах соответствующего изображения.

Заполняй reviewedViews только после полного визуального просмотра фрейма. Проверка без замечаний допускает пустой issues. При смене снимков нужен новый запуск и повторный анализ. Старый формат reviewedWidths/issue.width читается для совместимости лишь при однозначном соответствии ширины одному фрейму; для новых отчётов используй viewId.
